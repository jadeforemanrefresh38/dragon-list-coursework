Практический результат работы — веб-приложение Dragon list для ведения личных заметок с предустановленными метками. Исходный код и инструкция запуска входят в состав проекта.


## Введение

При работе с учебными материалами и личными планами возникает необходимость быстро сохранять небольшие записи и находить их по теме. Обычный текстовый файл не разделяет записи по категориям и не обеспечивает доступ через браузер с индивидуальной учётной записью. Поэтому разработка небольшого приложения для заметок имеет практическое значение.

Объект исследования — организация хранения личных записей в веб-приложении. Предмет исследования — средства Java для регистрации пользователей, управления заметками и фильтрации записей по метке. Цель работы — разработать приложение Dragon list, в котором каждый пользователь работает только со своими заметками.

Для достижения цели необходимо определить структуру страниц и базы данных, выбрать совместимые библиотеки, реализовать регистрацию и вход, операции создания, просмотра, редактирования и удаления заметок, а также фильтрацию. Отдельная задача — проверить ограничения доступа и подготовить приложение к развёртыванию на VPS с Debian 11.

В работе применены анализ требований, сравнение средств разработки, моделирование данных и интеграционное тестирование. Информационной базой служит официальная документация Java, Spring Boot, Spring Security, PostgreSQL и Thymeleaf. Работа включает выбор средств разработки, описание архитектуры и данных, практическую реализацию, проверку и заключение.


## 1 Выбор средств разработки

Для серверной части рассмотрены Java со Spring Boot, Python с Django и JavaScript с Express. Django предоставляет ORM и готовые средства управления пользователями, но использует другой язык. Express позволяет быстро создать маршруты, однако требует самостоятельно согласовать библиотеки доступа к данным, проверки форм и аутентификации. Spring Boot объединяет эти возможности через согласованные зависимости и соответствует условию разработки на Java.

Выбран Java 17 и Spring Boot 3.5.16. Преимущества решения — строгая типизация, зрелые библиотеки, транзакции и сборка приложения в один исполняемый JAR. Недостатки — большее потребление памяти по сравнению с небольшим скриптовым приложением и необходимость изучения конфигурации Spring. Для учебного проекта эти затраты оправданы возможностью явно разделить ответственность компонентов.

Интерфейс формируется на сервере с помощью Thymeleaf и обычного CSS. Такой подход позволяет реализовать пять требуемых страниц без отдельного клиентского приложения. Основное внимание уделено серверной логике. В оформление включены изображения драконов из предыдущего проекта; мобильная версия не разрабатывалась.


## 2 Архитектура и организация данных

Приложение разделено на контроллер, сервис, репозитории и модели данных. WebController принимает HTTP-запросы и возвращает HTML-страницы. NoteService проверяет владельца заметки и выполняет изменения в транзакции. UserRepository и NoteRepository предоставляют операции доступа к данным. Классы User и Note описывают сущности, RegistrationForm и NoteForm — данные входящих форм.

Spring MVC связывает параметры запроса с объектами форм. Bean Validation проверяет обязательность и длину полей. Spring Data JPA использует Hibernate для преобразования сущностей в строки таблиц. Flyway выполняет версионированную SQL-миграцию V1__schema.sql, а Hibernate при запуске проверяет соответствие схемы моделям. Создание схемы и её проверка разделены, что делает изменения базы данных воспроизводимыми.

Таблица users содержит id типа BIGINT, уникальный login длиной до 32 символов и password длиной до 100 символов. Поле password хранит хеш BCrypt. Логин нормализуется к нижнему регистру, поэтому записи User и user не создают два разных аккаунта. Ограничение UNIQUE предотвращает дублирование также при одновременной регистрации.

Таблица notes содержит id, user_id, title, content, tag и created_at. Поле user_id является внешним ключом на users.id: одному пользователю соответствует несколько заметок. Заголовок ограничен 200 символами, текст — 20000 символами на уровне формы. Метка обязательна и принимает только IMPORTANT, IDEAS, STUDY или PERSONAL. Пользователь видит названия «Важное», «Идеи», «Учеба», «Личное». Ограничение CHECK закрепляет список меток в базе.

Дата создания хранится как Instant и не изменяется при редактировании. В интерфейсе она отображается по московскому времени. Индексы по владельцу и дате, а также по владельцу, метке и дате соответствуют основным запросам списка. Для VPS предусмотрен PostgreSQL, для локального запуска и автоматических тестов — H2 в режиме совместимости с PostgreSQL.

Spring Security выполняет аутентификацию и хранит её результат в серверной сессии. Пароль при регистрации хешируется BCrypt; исходное значение в базу не записывается. Все операции изменения защищены CSRF-токеном. Выборка конкретной заметки выполняется методом findByIdAndUserLogin, поэтому изменение адреса в браузере не даёт доступа к записи другого пользователя. В этом случае возвращается код 404.


## 3 Реализация и проверка приложения

Сначала создан Maven-проект и подключены web, thymeleaf, data-jpa, security, validation, Flyway и драйверы баз данных. Версии библиотек определяются родительским проектом Spring Boot. Затем подготовлены SQL-миграция, сущности и репозитории. После этого реализованы сервис заметок, настройки безопасности и контроллер страниц.

Страница регистрации принимает логин и пароль. Логин состоит из 3–32 латинских букв, цифр или символа подчёркивания. Пароль содержит 8–64 печатных ASCII-символа, что удерживает его длину в пределах ограничения BCrypt. После успешной регистрации пользователь переходит ко входу. При ошибке показывается сообщение, пароль повторно в HTML не подставляется.

После входа открывается таблица с заголовком, меткой и датой. GET /notes возвращает все заметки текущего пользователя, GET /notes?tag=STUDY — только записи с меткой «Учеба». Список упорядочен по дате создания и идентификатору по убыванию. Пустая выборка сопровождается пояснением.

Создание выполняется через GET /notes/new и POST /notes. Страница GET /notes/{id} показывает полный текст. Для изменения используются GET и POST /notes/{id}/edit, для удаления — POST /notes/{id}/delete с подтверждением. После успешного сохранения сервер перенаправляет браузер, что снижает риск повторной отправки формы при обновлении страницы. Отдельный JSON API не создавался: взаимодействие построено на HTML-формах и HTTP-маршрутах.

Право доступа проверяется при просмотре, открытии формы редактирования, сохранении и удалении. Идентификатор владельца не принимается из формы, а определяется из текущей аутентификации. Текст выводится через th:text, поэтому HTML-код заметки отображается как текст. Ссылка поддержки появляется только после заполнения переменной DONATION_URL действительной HTTPS-ссылкой.

Автоматические проверки выполнены командой mvn verify. Три интеграционных теста охватывают регистрацию, вход, повторный логин, хеширование пароля, валидацию, CSRF, экранирование HTML, полный цикл CRUD, фильтр и неизменность даты. Отдельно проверены попытки просмотра, изменения и удаления чужой заметки. Итоговая сборка завершилась успешно. Дополнительно в браузере пройден сценарий регистрации, входа, создания, редактирования, удаления и выхода.

Тесты использовали H2 и настоящую миграцию схемы. Подключение к PostgreSQL на реальном VPS в рамках локальной проверки не выполнялось. Поэтому перед эксплуатацией необходимо проверить переменные подключения и выполнить контрольный сценарий на целевом сервере.


## Демонстрация работы и запуск

На рисунке 1 показан список с созданной во время проверки заметкой. На рисунке 2 — её полный текст, метка и действия. Снимки получены из работающего приложения.

Для локального запуска необходимы JDK 17 и Maven. Команда mvn clean verify собирает проект и запускает тесты; java -jar target/dragon-list-1.0.0.jar запускает приложение. Адрес в браузере — http://127.0.0.1:8080. Файловая H2 сохраняет данные в каталоге data.

Для Debian 11 подготовлены unit-файл systemd, конфигурация nginx и пример переменных окружения. На сервере устанавливаются Java 17 и PostgreSQL, создаются отдельные пользователь и база. Включается профиль prod, задаются DB_URL, DB_USER и DB_PASSWORD. nginx передаёт запросы приложению на localhost. До входа необходимо настроить HTTPS: в профиле prod cookie сессии передаётся только по защищённому соединению. Полная последовательность команд приведена в README проекта.


## Заключение

Разработано веб-приложение Dragon list на Java, реализующее регистрацию и авторизацию, создание, просмотр, редактирование и удаление личных заметок. Для каждой заметки выбирается одна из четырёх предустановленных меток; список можно отфильтровать. Серверная проверка владельца ограничивает доступ к чужим записям.

В ходе работы выбраны и согласованы библиотеки, спроектированы две связанные таблицы, создана миграция базы данных и выполнены интеграционные проверки. Браузерная проверка подтвердила основной пользовательский сценарий. Практический результат включает исходный код, исполняемый JAR и инструкцию для Debian 11. Возможность развёртывания подготовлена конфигурацией; фактическая установка на VPS остаётся отдельным этапом.

Первая версия рассчитана на небольшой объём личных записей. В ней отсутствуют пагинация, восстановление пароля и ограничение частоты попыток входа. В дальнейшем целесообразно добавить эти возможности, а также отдельную проверку на целевой PostgreSQL. Основные требования задания реализованы, а ограничения первой версии отражены в документации.
