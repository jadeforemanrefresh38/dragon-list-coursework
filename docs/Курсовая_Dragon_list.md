Практический результат работы — веб-приложение Dragon List с сервером на Java и интерфейсом для личных заметок. Приложение поддерживает Markdown, задачи, теги, черновики и корзину. Исходный код и инструкция запуска входят в состав проекта.


## Введение

При работе с учебными материалами и личными планами возникает необходимость быстро сохранять небольшие записи и находить их по теме. Обычный текстовый файл не разделяет записи по категориям и не обеспечивает доступ через браузер с индивидуальной учётной записью. Поэтому разработка небольшого приложения для заметок имеет практическое значение.

Объект исследования — организация хранения личных записей в веб-приложении. Предмет исследования — средства Java для авторизации, управления заметками и ограничения доступа к данным. Цель работы — разработать Dragon List, в котором каждый пользователь работает только со своими заметками, задачами и тегами.

Для достижения цели необходимо определить структуру интерфейса и базы данных, выбрать совместимые библиотеки, реализовать регистрацию, вход, операции CRUD и фильтрацию. Дополнительные задачи — автосохранение, Markdown, списки задач, черновики, корзина, настройки профиля и подготовка к запуску на Debian 11. Интеллект-карты в состав проекта не входят.

В работе применены анализ требований, сравнение средств разработки, моделирование данных и интеграционное тестирование. Информационной базой служит официальная документация Java, Spring Boot, Spring Security, PostgreSQL и Thymeleaf. Работа включает выбор средств разработки, описание архитектуры и данных, практическую реализацию, проверку и заключение.


## 1 Выбор средств разработки

Для серверной части рассмотрены Java со Spring Boot, Python с Django и JavaScript с Express. Django предоставляет ORM и готовые средства управления пользователями, но использует другой язык. Express позволяет быстро создать маршруты, однако требует самостоятельно согласовать библиотеки доступа к данным, проверки форм и аутентификации. Spring Boot объединяет эти возможности через согласованные зависимости и соответствует условию разработки на Java.

Выбран Java 17 и Spring Boot 3.5.16. Преимущества решения — строгая типизация, зрелые библиотеки, транзакции и сборка приложения в один исполняемый JAR. Недостатки — большее потребление памяти по сравнению с небольшим скриптовым приложением и необходимость изучения конфигурации Spring. Для учебного проекта эти затраты оправданы возможностью явно разделить ответственность компонентов.

Интерфейс перенесён из предыдущего проекта Dragon List и использует React, HTML, CSS и JavaScript. В браузере размещены боковая панель, список и редактор; доступны светлая и тёмная темы. Серверная логика полностью реализована на Java. Thymeleaf формирует страницы входа и регистрации, а готовая браузерная сборка включена в JAR: Node.js на VPS не нужен.


## 2 Архитектура и организация данных

Приложение разделено на контроллеры, сервисы и слой доступа к данным. WebController отвечает за страницы и формы регистрации. WorkspaceApi принимает JSON-запросы редактора, WorkspaceService проверяет владельца и выполняет изменения в транзакциях. Spring Data JPA используется для пользователей и учебных форм заметок, JdbcTemplate — для расширенных операций рабочего пространства.

Spring MVC обрабатывает запросы и связывает поля форм с объектами. Bean Validation проверяет формы, а сервис расширенного API дополнительно проверяет типы, длины и допустимые значения JSON. JdbcTemplate выполняет параметризованные SQL-запросы. Flyway применяет миграции V1 и V2, Hibernate проверяет совместимость сущностей со схемой. V2 расширяет базу без удаления существующих записей.

Таблица users содержит id типа BIGINT, уникальный login длиной до 32 символов и password длиной до 100 символов. Поле password хранит хеш BCrypt. Логин нормализуется к нижнему регистру, поэтому записи User и user не создают два разных аккаунта. Ограничение UNIQUE предотвращает дублирование также при одновременной регистрации.

Таблица notes сохраняет основные поля задания: id, user_id, title, content, tag и created_at. Миграция V2 добавляет статус active, draft или trashed, тип note или todo, позицию, закрепление, дату изменения и удаления. Дополнительные таблицы user_tags и note_tags связывают заметки с тегами; todos хранит задачи, profiles — настройки, media — проверенные изображения.

Дата создания сохраняется при редактировании, дата изменения обновляется отдельно. Индексы ускоряют выборку по владельцу и статусу. Для каждого пользователя создаются четыре исходные метки: Важное, Идеи, Учеба, Личное. Расширенная версия позволяет добавлять свои теги, менять цвет и назначать несколько тегов заметке. Для VPS предусмотрен PostgreSQL, для локального запуска и тестов — H2 в режиме совместимости с PostgreSQL.

Spring Security выполняет аутентификацию и хранит её результат в серверной сессии. Пароли хешируются BCrypt. Все изменения защищены CSRF-токеном. Каждый запрос заметки, задачи, тега и изображения ограничивается владельцем из сессии; чужая запись возвращает 404. Markdown отображается без исполнения исходного HTML. Загруженные изображения проверяются по формату, размеру и разрешению и перекодируются сервером.


## 3 Реализация и проверка приложения

Сначала создан Maven-проект с зависимостями Spring Boot. Затем подготовлены сущности и первая миграция с таблицами users и notes. Для переноса функций предыдущего проекта добавлены миграция V2, WorkspaceService и REST-контроллер. После этого браузерные компоненты подключены к Java API, а формы входа и регистрации приведены к оформлению старого проекта.

Страница регистрации принимает логин и пароль. Логин состоит из 3–32 латинских букв, цифр или символа подчёркивания. Пароль содержит 8–64 печатных ASCII-символа, что удерживает его длину в пределах ограничения BCrypt. После успешной регистрации пользователь переходит ко входу. При ошибке показывается сообщение, пароль повторно в HTML не подставляется.

После входа открывается рабочее пространство: навигация слева, список заметок и редактор. GET /api/notes/?status=active возвращает активные записи, параметры search и tag задают поиск и фильтр. Сортировка учитывает закрепление, позицию и дату изменения. Порядок списка меняется перетаскиванием; массовое действие применяется в транзакции, причём список с чужой записью отклоняется целиком.

Создание выполняется POST /api/notes/, редактирование — PATCH /api/notes/{id}/. Редактор автоматически сохраняет изменения с небольшой задержкой, сериализует запросы к одной заметке и показывает состояние сохранения. При ошибке текст остаётся в очереди для повторной отправки. Markdown имеет панель форматирования и режим просмотра. Списки задач поддерживают добавление, переименование, отметку выполнения и удаление пунктов.

DELETE /api/notes/{id}/ перемещает заметку в корзину; POST /api/notes/{id}/restore/ восстанавливает её. Окончательное удаление выполняется отдельным действием только для записи в корзине и подтверждается в интерфейсе. Черновики имеют отдельный раздел. Профиль позволяет изменить логин, email, описание, аватар и пароль. Ссылка поддержки перенесена из старого проекта без дополнительных рекламных подписей.

Командой mvn verify выполнены восемь интеграционных тестов. Они охватывают регистрацию, вход, хеширование, CSRF, CRUD и фильтрацию; расширенный API тегов, сортировки, массовых действий, задач, изображений, профиля и пароля. Отдельно проверяются обращения к чужим данным и отказ от неподдерживаемого типа заметки. Итоговая сборка JAR завершилась успешно.

В браузере проверены регистрация и вход, автосохранение с перезагрузкой, Markdown, теги, черновики, корзина, восстановление, задачи, сохранение темы и выход. Автоматические тесты используют H2 и обе миграции. На реальном VPS подключение к PostgreSQL пока не проверялось; перед эксплуатацией необходим контрольный запуск на целевом сервере.


## Демонстрация работы и запуск

На рисунке 1 показано рабочее пространство с заметкой в режиме просмотра Markdown. На рисунке 2 — список задач. Снимки получены из работающего Java-приложения после переноса интерфейса.

Для локального запуска необходимы JDK 17 и Maven. Команда mvn clean verify собирает проект и запускает тесты; java -jar target/dragon-list-1.0.0.jar запускает приложение. Адрес в браузере — http://127.0.0.1:8080. Файловая H2 сохраняет данные в каталоге data.

Для Debian 11 подготовлены unit-файл systemd, конфигурация nginx и пример переменных окружения. На сервере устанавливаются Java 17 и PostgreSQL, создаются отдельные пользователь и база. Включается профиль prod, задаются DB_URL, DB_USER и DB_PASSWORD. nginx передаёт запросы приложению на localhost. До входа необходимо настроить HTTPS: в профиле prod cookie сессии передаётся только по защищённому соединению. Полная последовательность команд приведена в README проекта.


## Заключение

Разработано приложение Dragon List с серверной частью на Java 17 и Spring Boot. Реализованы регистрация, авторизация и управление личными заметками, поиск и фильтры по тегам. Из предыдущего проекта перенесены интерфейс, Markdown, задачи, автосохранение, черновики, корзина и восстановление. Интеллект-карты исключены из согласованного состава функций.

В ходе работы выбраны библиотеки, спроектирована схема из семи связанных таблиц и созданы две миграции. Выполнены интеграционные тесты и браузерная проверка. Практический результат включает исходный код, JAR, подготовленные настройки systemd и nginx и инструкцию для Debian 11. Фактическая установка на VPS остаётся отдельным этапом.

Приложение рассчитано на небольшой объём личных записей. Список пока не имеет пагинации, отсутствуют восстановление забытого пароля и ограничение частоты входа. Регистрация открытая, как предусмотрено исходным заданием. Дальнейшее развитие включает эти возможности и проверку на целевой PostgreSQL. Основные функции реализованы, ограничения отражены в документации.
