# Dragon list

Приложение для заметок на Java. Интерфейс перенесён из предыдущего Dragon List: боковая панель, список и редактор, светлая и тёмная темы. Поддерживаются Markdown, автосохранение, задачи, черновики, корзина и восстановление, поиск по заголовку и тексту, теги с цветами, закрепление, перетаскивание списка и массовые действия. Интеллект-карты исключены по запросу пользователя.

Четыре исходные метки (Важное, Идеи, Учеба, Личное) создаются для каждого пользователя. В расширенной версии можно назначать несколько тегов, создавать и переименовывать их. Регистрация открытая. Профиль позволяет менять логин, email, описание, аватар и пароль. Поддерживается вставка PNG/JPEG/GIF в заметку (до 5 МБ и 4096 × 4096, GIF сохраняется первым кадром).

## Стек

Серверная логика полностью написана на Java 17: Spring Boot 3.5.16, Spring MVC, Spring Security, Spring Data JPA и JdbcTemplate, Bean Validation, Flyway. Maven 3.6.3+. Версии библиотек согласованы BOM Spring Boot. PostgreSQL для VPS, H2 для запуска без установки БД. Страницы входа и регистрации используют Thymeleaf. Браузерный интерфейс использует React 18, CSS и JavaScript из предыдущего проекта. Python-сервер не используется. Готовые браузерные файлы включены в JAR, Node.js на VPS не требуется.

## Локальный запуск

Установите JDK 17 и Maven. Проверьте `java -version` и `mvn -version`.

```sh
mvn clean verify
java -jar target/dragon-list-1.0.0.jar
```

Откройте http://127.0.0.1:8080 и зарегистрируйтесь. Данные сохраняются в `data/`; демонстрационных аккаунтов нет. H2 работает в файловом режиме. После перезапуска заметки сохраняются.

Для изменения браузерного интерфейса установите Node.js 24 и pnpm 11.25.0, выполните `pnpm install --frozen-lockfile` и `pnpm build` из `frontend/`, затем пересоберите JAR. Собранные файлы в `src/main/resources/static/frontend` хранятся в репозитории; обычная Java-сборка не требует пересборки интерфейса. CI пересобирает обе части.

## Debian 11 и PostgreSQL

Используется JDK/JRE 17 (Java 11 недостаточно). Приложение собирается с целевой версией Java 17. На VPS достаточно JRE 17 и PostgreSQL 13 из Debian 11. Сборку можно выполнить на другом компьютере.

```sh
sudo apt update
sudo apt install openjdk-17-jre-headless postgresql nginx
sudo -u postgres createuser --pwprompt dragonlist
sudo -u postgres createdb --owner=dragonlist dragonlist
sudo useradd --system --home /opt/dragon-list --shell /usr/sbin/nologin dragonlist
sudo install -d -o root -g dragonlist -m 750 /opt/dragon-list
sudo install -o root -g dragonlist -m 640 target/dragon-list-1.0.0.jar /opt/dragon-list/dragon-list.jar
sudo install -o root -g root -m 600 deploy/dragon-list.env.example /etc/dragon-list.env
sudo nano /etc/dragon-list.env
```

Впишите пароль PostgreSQL в `DB_PASSWORD`, оставьте профиль `prod`. Приложение подключается к PostgreSQL на localhost. Flyway создаёт таблицы, Hibernate проверяет схему. Пароль нельзя добавлять в репозиторий.

```sh
sudo cp deploy/dragon-list.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dragon-list
sudo journalctl -u dragon-list -n 50 --no-pager
```

Скопируйте `deploy/nginx.conf` в `/etc/nginx/sites-available/dragon-list`, замените `notes.example.com` на свой домен, включите конфигурацию ссылкой в `sites-enabled`. Проверьте `sudo nginx -t` и перезагрузите nginx. Настройте DNS и TLS-сертификат для домена, например через Certbot. В профиле `prod` cookie передаётся только по HTTPS: сначала настройте TLS, затем входите через домен. Порт 8080 слушает только localhost; извне должны быть доступны 80/443 и ваш порт SSH. Заголовки прокси доверяются при таком размещении за локальным nginx.

Резервная копия: `sudo -u postgres pg_dump -Fc dragonlist > dragonlist.dump`. Восстановление в пустую БД: `sudo -u postgres pg_restore --no-owner --role=dragonlist -d dragonlist dragonlist.dump`. Храните копии отдельно от VPS и проверяйте восстановление. Для обновления остановите сервис, замените jar, запустите сервис; перед миграциями сохраните копию БД.

## Настройки

`DB_URL`, `DB_USER`, `DB_PASSWORD` — подключение к БД. `PORT` — порт (8080), `SERVER_ADDRESS` — адрес (127.0.0.1). `DONATION_URL` задаёт HTTPS-ссылку поддержки (по умолчанию CloudTips из старого проекта: https://pay.cloudtips.ru/p/5a3bdc84). Пустое значение скрывает кнопку. `COOKIE_SECURE` предназначен для локального профиля; prod всегда требует HTTPS.

## Устройство и безопасность

Контроллеры принимают формы и JSON, сервисы проверяют владельца и выполняют изменения в транзакциях. SQL-запросы параметризованы. Запросы к заметкам, тегам, задачам и изображениям учитывают владельца из серверной сессии. Чужая и отсутствующая запись возвращают 404. Передача user_id через форму не используется. Пароли хешируются BCrypt; логины приводятся к нижнему регистру. Уникальность логина обеспечивается БД. Все изменения защищены CSRF-токеном, полученным при выдаче страницы. React экранирует текст; Markdown не разрешает исходный HTML. Изображения проверяются и перекодируются сервером, доступны только владельцу, резервируются вместе с БД. Лимиты: заголовок 200, текст 20000 символов, тег 50 символов, до 50 тегов на заметку, задача 500 символов, логин 3–32, пароль 8–64 печатных ASCII-символа.

Миграция V1 создаёт `users` и `notes` по исходному заданию. V2 сохраняет существующие записи и добавляет статусы, тип заметки, порядок, закрепление, дату изменения; таблицы `user_tags`, `note_tags`, `todos`, `media`, `profiles`. Четыре исходные метки и связи существующих заметок переносятся при первом открытии аккаунта. Метки расширенной версии находятся в `note_tags`; поле `notes.tag` оставлено для совместимости учебных форм. Время хранится с часовым поясом, браузер показывает относительное время.

Основной интерфейс: `/notes`. JSON API: `GET/POST /api/notes/`, `GET/PATCH/DELETE /api/notes/{id}/`, `POST .../restore/`, `POST .../hard_delete/`, `POST /api/notes/reorder/`, `POST /api/notes/bulk/`. Фильтры списка: `status=active|draft|trashed`, `search`, `tag` (название). Удаление через DELETE перемещает в корзину, окончательное удаление доступно только из корзины. Массовые действия атомарны: список с чужой записью целиком отклоняется.

Теги: `/api/tags/`, `/api/tags/dashboard/`, `/api/tags/{id}/`. Задачи: `/api/todos/`, `/api/todos/{id}/`. Профиль: `/api/profile/`, `/api/profile/save/`, `/api/profile/change_password/`. Изображения: `POST /api/images/`, `GET /api/media/{id}`. Резервные учебные HTML-формы: `/notes/table`, `/notes/new`, `/notes/{id}`, `/notes/{id}/edit`. Они используют одиночное поле метки из V1; основной редактор использует новые связи тегов.

## Проверка

`mvn verify` запускает 8 интеграционных тестов: регистрация, вход, хеширование, валидация, CSRF, CRUD и изоляция; API тегов, порядок списка, массовые действия, статусы, задачи, изображения, профиль и пароль. Тестовая БД H2 создаётся миграциями Flyway. В браузере проверены регистрация, вход, автосохранение с перезагрузкой, Markdown, теги, черновики, корзина, восстановление, задачи, сохранение темы, открытие настроек и выход. GitHub Actions собирает интерфейс и сервер на JDK 17.

Ограничения: список без пагинации, нет восстановления забытого пароля и ограничения частоты входа. Регистрация без кодов приглашения, как предусмотрено исходным заданием. Развёртывание на реальном VPS требует доступа к серверу и домена. Автоматические тесты на H2 не заменяют проверку PostgreSQL на сервере.

Дракончики перенесены из предыдущего проекта пользователя. Исходный файл задания сохранён отдельно и не изменялся.
